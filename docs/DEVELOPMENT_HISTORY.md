# 从桌游原型到 1.0.0

这份记录根据需求讨论、现有实现与验证记录整理。早期阶段没有独立版本标签，不虚构提交日期或逐提交历史。0.1.3–1.0.0 的整理及构建发生在 2026-11-01；更早的设备验证发生在 2026-10-30。它描述设计如何演进，不表示所有复杂桌游组合已完成实机验收。

## 1. 先让实体桌游在局域网跑起来

最初输入是说明书、37 种卡牌图鉴，以及一个在线桌游网站的呈现参考。目标是由一台主机保存和裁定游戏，其他人通过浏览器加入，也可以自行配置樱花穿透。

采用 Node HTTP 服务与原生网页，规则放在服务端，客户端只提交行动和选择。手牌权限、行动点、应对顺序、金币和胜利条件由同一套规则裁定，Windows 与 Android 不维护两套游戏实现。

基础流程逐步补齐为：创建房间、准备、掷骰排名、选座、初始选牌、顺时针回合、响应结算、结束与回放。两人酒馆、替换角色、EX 选择及人数牌库加入配置。自动化重点从单张卡扩展到结算队列、条件应对、手牌上限和完整模拟。图鉴中没有的剧本角色没有编造加入。

## 2. 暂离不是新玩家，认输也不是退出

早期返回房间依赖浏览器中的坐席凭据，出现“身份凭据无效”和“已在对局中但无法返回”。后续改用服务器账户关联坐席，登录后从服务器查找当前房间，同账号跨浏览器可以找回原身份。

将“是否还在房间”和“是否已认输”拆开处理：

- 准备阶段只有离开，不提供认输。
- 暂离保留对局身份；在房间仍存在时可以回来。
- 认输不可撤销，但仍留在牌桌看结果、聊天，结束后可以返回准备房间。
- 退出观战才真正离开；不能把认输自动当作回大厅。
- 房主是可转交权限，不是房间所有者。各阶段离开按顺时针转交，最后一人离开才解散并释放房间号。
- 全员离开未完成对局记为中止，清理结算队列并保存记录，不给任何人判胜或判负。

修复覆盖选座、初始选牌、游戏中、回放中返回，以及旧轮询覆盖新登录状态。旧版本无人房间在启动时清理。

## 3. 回放与共享数据不能跟着一个账户消失

从最近三局扩展到每人最近五局；回放按操作快照提供全知视角，支持步进、拖动与自动播放，参赛者包括已认输玩家。

永久删除只清理该人的资料、凭据和索引。仍有其他参与账户时，保留共享回放和其他人的统计；最后一个参与账户永久删除后才清理无人关联的回放。注销是可恢复停用，不能等同永久删除。

后台区分当前房间和共享回放，显示数据目录与删除影响。删除正在对局的账户前展示阶段、房主状态等信息，确认后先按认输处理并转移房主。另有独立确认的“清空所有测试数据”，避免为重测而误删共享数据。

个人信息增加累计参与、有效对局、中止对局；胜率用胜场除以有效对局。中止不会填入最近三局成就窗口。统计写入做幂等处理，避免重启或重复保存多算。

## 4. 身份、名片与忘记密码

加入登录注册、服务端统计、昵称首字头像、自定义单字颜色和 37 个角色头像。用户可以佩戴一个词条，在名片展示三个词条，点击头像查看战绩。

忘记密码采用本机管理员核实身份后重置临时密码。密码存 scrypt 哈希，原密码不可还原；重置撤销旧会话，临时密码默认遮挡，首次登录要求更改。没有为了后台“查看”改成明文存储。

成就依据后续明确的口径修订：

- “绝不回手之人”改名为“绝不还手之人”：最近三局完成对局主动应对合计不超过 10 次。
- “惨！！”：最近三局完成对局全输。
- “休想得逞”：至少一局有应对机会，全部接受且成功结算。
- “王国座上宾”“魔物的挚友”：比较累计主动选择两阵营牌的数量，持平不授予。
- “强盗”：累计抢夺至少 10 枚金币，商人交易不算抢夺。

历史数据只补可确认统计，不凭缺失记录推断应对成功或阵营选择。

## 5. 配置需要预设，也需要可控覆盖

替换角色原来互斥，后来为每组增加“双角色启用”。基础 / 替换角色与 EX 分别支持全部启用，人数与预设更新默认数量，最后由每种牌的自定义数量覆盖。禁用的牌不会被旧数量意外重新加进牌库。

修复保存设置时误读牌桌上的 `data-count` 属性，导致未修改也报“每种牌 0–12”的问题。仅从设置表单读取，非法值定位到具体卡牌，错误提示提升到浏览器顶层；合法保存关闭设置窗口，让非房主重新准备。

游戏进行中改为“本局游戏详情”列出组成与约定，不再展示大量可修改规则。房主直接暂停 / 恢复，其他人申请，由房主审批。

## 6. 牌桌密度、美术与可读性

由最初可拉伸模块改为记录 / 牌桌 / 聊天三栏，取消牌桌与聊天分隔的手动调节。多人局对手区域采用响应式多列，保证卡牌可读；常规电脑尽量少滚动，复杂场面允许自然滚动，侧栏各自滚动。

接入用户提供的战场、阵营牌背、徽记、单张拉伸木纹、金币、骰子、状态、胜负及成就素材。头像框和序列特效遮挡内容，按反馈撤除；透明底素材替换后保留静态图标。房主图形徽章不清晰，撤掉后保留文字提示。

后续仅添加克制的操作反馈，避免遮盖牌面。复用卡牌图片节点，解决刷新时牌背牌面闪烁。场上牌正面公开，手牌只露阵营背面；选择他人未知手牌时由服务端重新随机顺序。

字号支持 12–22 像素。普通文本框关闭自动填充，账号密码保留正确的凭据填充语义。

## 7. 让记录能解释“发生了什么”

从简短动作改为附带牌名、目标、等级 / 纹章判定、金币变化与公开宣言的记录。人名按座位醒目渲染，牌名按阵营配色，悬停或键盘聚焦可查看效果。

所有攻击都进入应对询问，即使目标没有合法应对牌也可明确放弃，避免通过“没有弹窗”泄露手牌信息。蝙蝠私人看牌窗口关闭 X 与确认按钮统一确认，避免重复弹出；旧确认请求不能覆盖新房间状态。

弃牌区先展示最新三张，其余堆叠可展开。非持续场上牌在自己准备阶段自动回手，持续牌留场，不能把回手当作再次获得卡牌重复统计。

## 8. 主机软件：Windows 与 Android

主机安装软件，玩家依旧使用网页。启动器支持空闲端口自动分配、指定端口、地址复制、管理入口和存档位置；固定端口供穿透使用。存档互斥锁防止两个新版服务写同一目录。

Windows 使用 WinForms 外壳与随包 Node；Android 使用前台服务、JNI 桥和嵌入 nodejs-mobile，复用同一份服务端与网页。补齐 SDK、NDK、CMake、共享 C++ 运行库，解决原生依赖缺失及 Unicode 正则兼容性；构建经 ASCII 临时目录解决 Windows 中文路径下的链接问题。

两个平台用 `assets/app_icon.png` 生成系统图标。Android 改为横屏深色金色控制台，与 Windows 风格一致。手机网页横屏使用，浏览器不会被强制旋转。

曾出现启动时旧网页闪现。先遮住首屏，再接入确认过的 HTML 开场；开场与数据加载并行，二者完成才进入登录。背景、黑边、徽记和标题位置与登录页对齐，减少跳转突兀感，支持跳过、失败重试和减少动态效果。

## 9. 本机统计与全知观战

控制台显示在线人数、现存房间和进行中的对局。在线按 30 秒内有认证心跳的唯一账户统计，多标签页不重复计人。

本机只读全知观战用一次性票据建立独立会话，不占玩家席位、不替玩家保活，也不阻止空房间解散。进入写入对局记录。最终界面统一为“观战”，页面由 `gm.html` 改成 `gz.html`；兼容内部接口仍使用 `/api/gm`，不开放对局控制命令。

## 10. 1.0.0 收口

字号旁加入玩法介绍与完整图鉴。图鉴支持名称 / 效果 / 纹章搜索，按阵营、效果类型、基础 / EX 筛选。两者均为浮窗，可拖动、缩放、关闭和切换置顶；置顶使用浏览器 top layer，在游戏设置等对话框打开后重新置前。

发行与源码目录分开。源码使用文件白名单导出，排除真实账户、存档、管理密钥、备份、签名密钥、构建工具和旧发行包。补充 README、版本日志、构建文档、资源权利说明及本演进记录。

## 11. 2.0.0 规则与交互校正

在首版导出后，用户要求积累修改、最后集中测试。龙幼崽改为发动者逐个选择目标收回哪张牌；酒馆与弃牌堆拿牌公开牌名；主动弃牌限制为行动点为零、超过四张且没有未结算效果。强盗成就仅统计从其他玩家处抢夺的金币，自产与交易另计。

根据用户填写的文案审核表应用 32 项修改，包括 29 项文案与 3 项规则说明纠正。明确金币来自哪名玩家、攻击牌放置或弃置、应对台词、纹章与等级判断；炸弹怪由当前持有者收回自己的另一张牌，妖精只收回自己的场上牌，牛头人列出交付数量及牌名。用户填写的审核表保留原样，未纳入公开源码，最终规则与文案写入代码和图鉴。

新增全体其他参赛者一致同意的回退，含认输观战者；申请期间冻结操作。保留最近二十步，恢复牌区、行动点和待选提示，冲回相关统计并保留聊天、标记撤销记录。离开或认输取消申请并清理历史，结束后不再回退。已被看到的信息不能因此恢复秘密。

为减少误点，选牌先预览再确认；暗牌仅展示阵营牌背。暂停、回退或提示变化使旧确认失效。可主动发动的持续牌先看详情，再点击独立“发动”按钮。图鉴增加无等级与 Lv.0–Lv.5 条件。

## 12. 2.0.0 同步与性能

保留原生 HTML / CSS / JavaScript，不为动效引入 Vue 或 React。HTTP 继续处理静态页面、命令与回放，在同一个服务器与端口上挂载纯 JavaScript `ws`。浏览器按玩家身份接收过滤后的实时状态，限制来源、认证与消息体大小，使用心跳保活；断线退回 1.5 秒 HTTP 同步并指数退避重连，恢复后停止常规轮询。HTTP 未变化状态仅回传版本号。

不能仅将 HTTP 等同于每次新建 TCP：浏览器通常复用连接。本次优化针对轮询等待、反复发送完整状态、同步落盘、完整历史复制及前端重复布局。服务端用异步临时写入后替换文件，合并待写版本；正常命令确认前等待持久化。启动恢复仍同步完成，房间草稿只复制可变实时部分，回放与回退快照共享不可变条目。

客户端按版本与会话拒绝旧快照，缓存玩家区块、聊天、弃牌和记录，未变化区域保留节点。操作请求设超时，超时只重新同步，不自动重试可能已执行的操作，避免重复出牌。

## 13. 2.0.0 动效与发布

用浏览器 Web Animations API 增加可见牌区间移动、手牌位置整理、攻击目标反馈和按压反馈。暗抽用牌背；动效不阻塞服务器操作，不改变规则节奏。限制同时播放数量，切换房间、回放、暂停或回退时清理；支持减少动态效果和不支持动画的降级。这是本轮交互反馈实现，不宣称达到《杀戮尖塔 2》的完整动画表现。

此前待测试修改与本次实时改造集中回归，包含 40 局完整自动模拟、五客户端个性化实时推送、并发操作、持久化、重连、权限和选牌确认。Windows / Android 构建都携带同一锁定依赖，源码包排除运行时依赖目录并提供 `npm ci` 构建步骤。新版本独立存放，保留 1.0.0 成品与真实数据。

## 14. 2.0.0 安卓实机修复

Mi 10 Pro 上发现启动时在 decor view 创建前访问系统栏控制器导致空指针，改为 setContentView 后通过 root.post 获取并判空。服务器重启时，存档中旧的 lastSeen 会使恢复房间在首次离线巡检被解散；增加 60 秒重连宽限，玩家状态仍如实判断，不虚报在线。

在该设备验证原生面板、局域网访问、双客户端 WebSocket、聊天、准备 / 选座 / 发牌、出牌、暂停审批、回退、暂离返回、全知观战、在线统计和重启恢复。屏幕录制看到来自另一客户端的公开出牌动效；未宣称穷尽所有规则组合。相关临时测试账户已清理。

## 15. 3.0.0 音频与顶栏

用户提供 5 首音乐及 24 项音效，准备房间使用 bgm_lobby(1).mp3，回放音乐为 WAV。音效和 BGM 两组控件紧邻字号，各自控制启用和音量，并保存在当前浏览器。登录页保留同一组声音控件，登录后移回 appbar。

声音由新状态中的公开事件驱动，而非只响应本机点击。他人出牌也可听到；盲抽不区分隐藏卡牌，私有应对提示只对本人播放。首次快照、断线恢复、回放跳步不追播旧事件；回退清理待播队列。限制同时播放数量和队列长度，切到后台立即停止，前台继续当前场景 BGM。遵守浏览器播放限制，首次点击或键盘操作后启用声音。

原始 WAV 由流式编码器留下 0xffffffff 长度；只修正发布副本 RIFF / data 长度字段，不转码、不修改 PCM、不覆盖原始素材。HTTP 音频单独用流传输，支持 Range、正确 MIME 和版本化缓存，避免读整首音乐到内存。

appbar 所有字号、尺寸、间距改为 px，消除根字号滑块对顶部布局的影响。手机窄屏改成紧凑按钮，保持字号 / 声音 / 玩法 / 图鉴 / 设置可达。3.0.0 独立发布，纳入原先未重新打包的实机修复，旧版本与真实数据保留。

## 16. 3.0.1 音频、选牌来源与缓存

用户报告手机浏览器在播放音效后 BGM 无声。将多个 HTML Audio 音效播放器改为单一 AudioContext 内的解码缓冲音效；背景音乐继续流式播放，通过 MediaElementSource 接入同一输出，分开控制两路增益。补齐首次解锁时设置 src 的顺序、意外暂停恢复、前后台切换、过期音效取消和失败加载重试。新设备默认音乐 100、音效 70，已有本机设置保留。该改动针对媒体输出竞争，真实设备的最终听感仍需确认。

女巫在同一名字同时出现在手牌和场上时，过去选项只有牌名；现在统一为有实例的可见卡牌添加来源。龙蛋从牌库与弃牌区检索同名牌也能辨别；场上持续牌标记横置状态。暗牌选择仍然随机排列，不添加隐藏牌名或牌库位置。

资源按音乐、卡牌、其他素材的顺序后台预加载，限制并发，不阻塞登录。沿用普通 HTTP 缓存，适用于局域网明文 HTTP；无需依赖要求安全上下文的 Service Worker。图片与音乐 30 天有效期从下载 / 校验响应计算，登录不延长；空间不足时浏览器仍可清理。自动补齐不扣额度；手动重新获取使用 reload 更新原地址缓存，而非增加随机 URL 浪费空间。

手动刷新额度由服务端按账号持久化，按北京时间每天一次。后台可临时授予当日额外一次，不叠加未使用临时额度。客户端记录任务和已完成文件，同日失败后继续剩余资源，不重复扣次。这限制的是平台按钮，不能限制用户清空浏览器缓存、开发者工具或直接访问公开素材。

“玩法介绍”改为“介绍”，分为玩法 / 平台两个选项卡。平台页覆盖主机连接、准备配置、牌桌操作、暂停回退、暂离认输、账户名片、回放观战和声音缓存；保留拖动缩放、置顶与关闭，增加键盘选项卡导航。按用户要求先完成源码与测试，3.0.1 成品等待确认后再打包。

## 17. 4.0.0 回放加载与三语言

用户在 Windows 测试后要求：进入回放时锁定并显示等待，避免重复点击；增加日语和英语，完成后发布 4.0.0。大厅和牌桌两个入口共用加载状态，禁用列表按钮，直到进入或失败才恢复。网络失败可再次点击，旧会话完成的请求不再进入回放；实时更新期间不替换正在等待的列表节点。

网页顶栏、登录、观战、后台增加语言选择，本浏览器保存偏好。同房间的其他人不受影响。词典包含完整 37 卡名称与效果、选牌来源、成就、声音 / 资源面板、系统提示；规则和平台介绍分别提供完整段落译文，图鉴搜索同时匹配原文和译文。翻译只作用于显示层，不改变卡牌实例、规则判断、原始日志、昵称、聊天和输入值。原卡面位图没有重绘，详情文字提供译文。

动态页面保存文本节点的原文和当前译文，语言来回切换不把旧译文当作新原文；新增提示与标题属性同样处理。日志中玩家引用、聊天、头像和明确的用户内容跳过翻译。选牌中的玩家目标与卡牌名称区分，避免昵称恰好叫“公主”时将用户名字变成牌名译文。回放按钮恢复时取原始标签，避免切换语言后留存上一语言。

Windows / Android 原生主机面板也能选三种语言，共用由词典生成的 JSON；打开浏览器时通过 lang 参数带入选择。Android 补充应用名称和前台通知的语言资源。网页和主机均不依赖外部翻译接口。未变化的音频继续用 3.0.1 素材 URL，避免仅升级软件就重下音乐。

4.0.0 单独构建 Windows、APK、源码和发行 ZIP，保留 3.0.0、3.0.1 Windows 测试版及真实服务器数据。构建文档记录词典生成、工具链、原生库验证、签名和校验方法；具体通过的检查见版本验证记录。

### 日语开场修订

首次 4.0.0 发布后，用户报告日语启动动画卡住。排查发现开场状态文字每帧重写，翻译器监听自身写回又触发额外检查。将 6.4 秒开场的阶段更新从数百次缩减为 4 次；动态翻译按 16ms 批处理，翻译写入时断开自身监听并在结束后恢复，防止翻译更新反过来挤占动画。

回归测试模拟真实的文本与属性变更通知，验证中、英、日的四个阶段均能翻译且自身写回不追加通知，并按 16ms 步进检查开场按时完成。两项强化检查在旧包代码上失败、在修订代码上通过；这属于代码级复现，不代替用户设备的动画验收。同版本重建两端及工程、发行压缩包，并重新生成校验文件。旧包备份置于本机 outputs，真实存档保留。

## 18. 5.0.0 格斗家、魔剑与牌桌局部弹窗

用户明确空手得分仅为得分约定，不应限制格斗家打出。因此撤去“手里必须还有牌”的合法性限制，将空手开关移入金币判定。两张格斗家中，效果实际放置的另一张为 Lv.0，0 是偶数，正常得分；妖精等无等级纹章牌不可当作 0 求和，记录直接解释失败原因。

魔剑旧实现先要求选择一种颜色，再把勇者目标限制到那种颜色。改为横置立即赋予“本回合下一张适用勇者可指定任意颜色手牌”，候选同时含两种颜色且仍隐藏牌面。保留结算留场、房间勇者系列约定及效果消耗，排除狂战士，兼容旧存档已选择的魔剑状态和待完成颜色请求。

牌桌弹窗从原生全局模态改为局部非模态，遮罩及应对面板只覆盖 table-panel，几何位置在滚动、窗口与牌桌尺寸改变后更新。牌桌 inert 阻止键盘与鼠标穿透，聊天、记录和顶部工具继续可操作；选牌确认、回退投票、卡牌、设置及资源查看采用统一入口。认输、回退申请与资源下载确认也改为异步局部窗口，防止浏览器原生确认框仍然锁住整页；确认防重复并校验会话，多个窗口按打开顺序置前。准备房间、登录页面及独立后台维持原有模态行为，避免改变账户认证流程。

新增格斗家组合与开关、魔剑双阵营候选、效果消耗与失效、旧状态兼容、局部弹窗边界及交互释放的回归检查。测试结果和两端发行验证见 VALIDATION-5.0.0.md。保留旧发行包与真实服务器数据，独立生成 5.0.0 成品。
